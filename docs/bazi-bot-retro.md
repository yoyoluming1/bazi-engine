# 做一个会算盘的命理 bot：技术复盘

> 目标不是「做一个算命工具」，而是回答一个问题：**当我们把一件事交给模型去「说」的时候，怎么保证它说的东西是算出来的，而不是编出来的？**

## 一、拆题：算 与 说

市面上的「命理 AI」大多长这样：一段精心写的提示词 + 一个知识库。模型输出「你今年财星旺，适合跳槽」——听起来对，但**没有人知道它凭什么这么说**。

这件事的根子在：模型擅长语言，不擅长计算，而且**它不会告诉你它没算**。

所以第一步是把问题拆成两半：

| 层 | 谁负责 | 判据 |
|---|---|---|
| 算 | 代码 | 可测试、可复现、有对照 |
| 说 | 模型 | 只能引用算出来的结论，不能自己发挥 |

拆完之后，第二个问题才有意义：**怎么让模型「只能引用」？**

答案是工具（function calling）：模型看不到盘，它只能调 `bazi_chart` 拿到结构化结果，然后基于结果组织语言。

## 二、算的部分：四个真问题

### 1. 真太阳时（最容易被跳过，也最容易错）

命理排盘用的是**当地真太阳时**，不是钟表时间。偏差有两个来源：

- **经度**：中国统一用东经 120° 的区时，北京在东经 116.4°，实际太阳时比钟表慢约 14 分钟。
- **均时差**：地球轨道是椭圆、地轴倾斜，一年内还有 ±16 分钟的变化。

两者叠加，北京冬天出生的人可能和钟表时间差 **24 分钟**。

这不是小事。时辰的边界是整点两小时一段，**差 20 分钟就可能跨过边界，时柱整根换掉**。

我们的实现（`src/solar-time.mjs`）用 Spencer 近似式算均时差，误差 30 秒以内，对排盘绰绰有余。测试里专门埋了一个用例：

```
09:05 出生（北京经度）→ 真太阳时 08:41 → 时柱从「巳」变「辰」
```

不加这一步的软件，这张盘就是错的，而且**错得毫无痕迹**。

### 2. 历法：不自己造轮子

节气交接、干支纪日、农历转换——这些交给 `lunar-javascript`。理由很简单：**正确性优先于原创性**。自己写历法算法，错在润月和节气交界的概率极高。

界线划在这里：**历法用库保证准确，规则自己写并测试**。

### 3. 力量与强弱：把假设写在明处

身强身弱需要给五行打分。权重怎么定？各书不同。我们的做法是把权重写成常数并注释：

- 天干 1.0
- 地支藏干：本气 1.0 / 中气 0.5 / 余气 0.3
- 月令加成 ×1.5

然后输出一个**比值**（帮扶 / 总量）和档位，而不是一句「你身弱」。换一本书，改这几个常数即可——**流派差异变成了可配置参数，而不是不可见的黑箱**。

### 4. 调候：与扶抑正交的第二个维度

扶抑回答「强了该泄该耗，弱了该生该扶」；调候回答「生在盛夏还是寒冬，这盘该润还是该暖」。**两个问题正交**，所以必须并列输出，不能互相覆盖。

调候用《穷通宝鉴》的「月令 × 日干」表，120 格。表按通行摘要转录，各家版本有出入——这一点写进了 README 的局限清单，也写在代码注释里。**知道自己的边界，比假装完整重要。**

## 三、说的部分：两层约束

### 1. 工具层：只给一只手

这个 bot 跑在对公网开放的服务上，所以 profile 里只放行 `bazi_chart` 一个工具，其余（shell、文件、子代理、工作流……）全部禁用。24 个插件行被关掉。

理由：**任何工具都可能被提示注入利用**。一个只会排盘的 bot，被注入也只能排盘。

### 2. 人设层：五条硬契约

- 不说不吉利的话（不用「大凶」「必败」，不预测灾祸疾病）
- 每个结论后面跟一句「怎么看出来的」
- 不替用户做重大决定
- 缺出生时间先问，不编
- 术语出现后跟一句白话

这几条不是「风格偏好」，是**产品边界**。命理内容很容易滑向恐吓式营销，契约是刹车。

## 四、踩过的坑（都是真坑）

1. **DSH 的 schema DSL 不支持顶层 `required` 数组**——必须用属性级 `required: true`。写插件才会知道。
2. **pnpm 复制 file: 依赖，不软链**——插件里用 `../src/x.mjs` 相对路径，装进 profile 就断。必须声明成包依赖。
3. **`file:` 依赖不装传递依赖**——`lunar-javascript` 没被带进去，运行期才炸。
4. **管理型 profile 命令行改不动**——桌面应用的 profile 由应用独占，`dsh plugin add` 会直接拒绝，得走应用自己的插件管理接口。

这四条没有一条能从文档里查到，都是撞出来的。

## 五、结果

- 引擎 + 插件 + 网页：**37 条测试**
- 排盘覆盖：真太阳时、四柱、十神、五行力量、身强弱、大运流年、格局、扶抑用神、调候、地支关系
- 每个结论都带 `basis`，模型被要求引用它

最直观的一次验证，是让模型自己排完盘后写的这段：

> 月干辛七杀紧贴日主，时干庚正官隔在另一头……丙辛合水，伤官合杀，是你自己用表达把压你的东西化掉了。

这句话里的每一处（哪个字在哪个柱、什么十神、什么合）都能在工具输出里找到对应行。**它不是在"感觉"，它是在读数据。**

## 六、还没做的

- 神煞（几十种，判定标准混乱，工程上没难度但容易变成堆数据）
- 合化的成立条件（现在只标关系存在，不断言化不化）
- 格局高低、用神的动态变化

这些不是做不了，是**先把能算准的部分做准，再谈算得更细**。
